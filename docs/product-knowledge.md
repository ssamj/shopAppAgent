# 商品知识检索与来源核对

本功能面向售前商品咨询，例如比较两款针织衫的护理负担。商品 ID、成分和款式继续通过商品接口查询；价格、SKU 库存和订单状态不进入向量索引。知识资料只提供说明文本、适用条件和来源。功能默认关闭，先完成迁移、模型准备与索引，再启用。

未启用知识功能且尚未迁移的环境，普通会话仍可保存和回看；带来源的知识回答需要完成下面的迁移。

## 安装与启用

运行 `npm ci` 安装依赖。已有数据库执行 `npm run db:migrate:knowledge`，新增知识表和消息引用字段，保留业务数据与用户编排提示词。新库初始化也会建立这些表。

依次执行 `npm run knowledge:prepare` 与 `npm run knowledge:index`。前者首次从 Hugging Face 下载固定修订的 `Xenova/multilingual-e5-small` q8 模型到 `.local/embedding-cache`；后者使用本地模型为资料建立索引。模型授权为 MIT，模型与缓存不进入 Git。后续业务检索只允许本地加载，缺少模型时明确失败，不在请求中静默下载或切换模型。

在自己的本地配置中增加 `"knowledge": { "enabled": true }`，然后重启智能体与业务服务。原有数据库与聊天模型配置不变。独立环境可用 `QIHE_CONFIG_PATH`、`QIHE_AGENT_PORT`、`QIHE_BUSINESS_PORT`、`QIHE_WEB_PORT` 指定配置和端口。

`QIHE_EMBEDDING_CACHE` 可指定模型缓存位置；模型准备、索引与服务启动必须使用同一位置。无需额外 Embedding API Key，不修改现有聊天模型连接。

## 资料与索引

`data/knowledge/manifest.json` 声明文档名称、版本、文件、适用商品和可见范围。示例资料都是虚构教学商品的说明，不代表真实品牌、供应商或实物洗标。实际使用应替换为有权使用并核实的资料。

按 Markdown 二级标题切分完整条款，保留限定和例外。超过长度限制时明确失败，须调整资料；不截断条款后继续建立索引。向量维度 384，查询与文档分别使用模型规定的 `query:`、`passage:` 前缀，平均池化后归一化。

当前为小规模实现：PostgreSQL 原生数组存储向量，应用按商品和角色过滤后计算精确余弦相似度；不依赖 pgvector，不使用近似索引，也不声称经过大规模性能验证。每个商品最多取 3 个候选，通用资料另取最多 2 个。第一名不一定包含答案，分数不是正确率。未设置“超过某分数即可相信”的阈值。

导入时先完成所有片段向量计算，再在事务中写入新索引并切换生效版本。失败不会使半成品索引生效，旧版本保留；同内容和模型重复导入不重复建立当前索引。更换模型必须重新生成整份索引，运行时拒绝模型标识或维度不一致。

## 调用与回答

`knowledge_search` 是只读注册能力，参数为 `query`、`productIds`、可选 `limitPerProduct` 与 `includeGeneral`。模型根据上下文提出查询；程序不通过尺码、面料、护理关键词分流。服务端检查身份、商品可见性、Schema 和索引；向量计算在 SQL 事务之前完成。

返回原文片段与文档、章节、版本、商品范围、内容哈希和索引版本。通用资料不能证明某款商品允许某种洗护方式。没有文档返回成功空结果；有相关片段但没有问题所需信息，也应明确说明本轮依据不足。模型缺失、索引缺失、内容损坏和技术异常明确失败。

模型在知识回答中输出 `answerBlocks`，包括正文、事实/建议/资料不足的类型、涉及商品与来源 ID。`message` 为空，最终文字由经过校验的段落组成。事实和建议必须带出处；引用只能来自本轮实际传入模型的片段，完整条款被上下文裁剪后不能继续引用。模型只选择来源 ID；展示原文由程序从检索结果直接带出，禁止模型提供 quote 字段替换原文。程序验证来源哈希和商品范围，失败时结束当前运行，不自动重试、不修改模型结论或恢复为普通成功回答。

引用核验不等于语义证明。模型仍可能漏查、误解原文，或把事实错误地标为资料不足；引用存在也不能证明结论必然正确。具体准确性需检查实际查询、片段和答案，不能宣称消除了幻觉。

来源快照随消息 `answer` 一起保存。刷新、回看历史时显示回答生成时的版本，而不是用新文档替换历史原文。前端可用键盘展开出处，显示教学资料标识。检索资料是数据，不具有改变权限或执行写操作的授权。

护理便利性要求保留在现有需求摘要及近期原话中，不强塞进面料字段；本功能不新增跨会话偏好，也不保证长对话中任意护理约束都已完善。

## 验证

- `npm run verify:knowledge:unit`：来源、引文、商品范围、裁剪和协议边界，不调用模型。
- `npm run verify:knowledge:storage`：真实本地向量及隔离数据库验证，要求显式 `QIHE_CONFIG_PATH` 指向 episode05 隔离库、`QIHE_ALLOW_WRITE_TESTS=1`；资料状态夹具事务回滚。
- `npm run verify:knowledge:runtime`：明确的模型响应夹具＋真实知识 API，验证错误来源、模型伪造原文、跨商品引用、缺少结构和非法参数会结束运行；仅在隔离库创建测试会话。

这些确定性检查与真实聊天模型的咨询验证是不同证据，不能互相代替。真实模型验证消耗现有模型额度，应使用独立会话和隔离业务库。
